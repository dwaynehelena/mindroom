## Portfolio invariants

- Consequential execution stays disabled until Project 3 authorizes the exact executable payload, not merely a redacted preview.
- No runtime may silently fall back from an authenticated remote/gateway path to local execution.
- Secrets and private content must not enter logs, process arguments, approval previews, heartbeat output, or provenance exports.
- Every external write must be attributable, idempotent where supported, and recoverable without duplicating uncertain side effects.
- Telegram status is delivered through the canonical Matrix portal and its authorized alias mapping.

## Implementation order

1. Complete Project 3's exact-payload authorization seam and adapters.
2. Complete Project 1's gateway-only transports using that authorization seam.
3. Build Project 6 once as shared evidence infrastructure.
4. Build Projects 2 and 7 on the shared provenance/trace contracts.
5. Build Project 4, then Projects 5 and 9 as its trusted execution substrate.
6. Re-run Project 8's reversible OpenClaw gateway write under a supported Node runtime; the service composition and concrete executors are implemented.
7. Close with Project 10 using the registry, recorder, approval, and canary foundations.
